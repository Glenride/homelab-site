The Omarchy install died halfway — blame the SD card, not the hardware

by D'Vaughn House

The goal

Get Omarchy (Arch-based) installed on a 2017 27" iMac to turn it into the always-on homelab server. Simple enough — or so it seemed.

Hardware and cost

  • 27" iMac (2017)
  • SanDisk Extreme Pro SD card in a USB adapter as install media
  • Spare SD card from my Zoom recorder (the backup plan)

Software stack

  • Omarchy — the Arch-based distro being installed

What broke and how it was fixed

It started with an earlier attempt that died uglier: I tried writing the Arch ISO as a raw disk image onto an NVMe partition and the boot failed with a bad-superblock error — the medium was unreadable before anything ever loaded. Then the Omarchy installer "crapped out" about 5.8GB in with bad package reads, and the iMac was stuck in a boot screen — macOS gone, nearly the entire OS installed, and the Limine bootloader showing blank entries with "Boot protocol not specified for this entry."

The first theory was a corrupt ISO download. Wrong. The real discovery: the SanDisk Extreme Pro SD card itself — sitting in a USB adapter — was dead — "unreadable by the computer" on both of my Macs. I thought it was a file type issue at first. It wasn't. The card was gone.

The backup plan was the SD card in my Zoom recorder. In my own words at the time: "I have another card I can use that I use for my zoom recorder. if that one breaks I am fucked." It didn't break. The recordings got copied to the Mac Studio first, then the card got reflashed with Omarchy.

Two more hurdles on the way: the failed install had written its bootloader to the internal drive, so the firmware kept booting straight to the dead entry instead of scanning for the SD card — an NVRAM reset (Option+Command+P+R) forced a fresh scan. And I had no USB drive at all ("I don't know where it is"), so the whole recovery ran through SD cards.

The lesson: when an installer dies mid-read, suspect the medium before the machine — and when a card dies on two different computers, it's the card. The cheapest, dumbest part of the chain is usually the guilty one.

Verdict

If your Linux install dies mid-flight with read errors, suspect the install media first. Five minutes reflashing a drive beats an hour of RAM surgery. Every time.
