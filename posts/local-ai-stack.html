My local AI stack, and why I run my own infrastructure

by D'Vaughn House

The goal

Do serious AI work — models, agents, image generation — on hardware I own, so the work continues no matter what a subscription costs next year. This isn't a hobby setup. It's the backup plan.

Hardware and cost

  • Mac Studio (M2 Ultra, 64GB unified memory) — model serving over the home network
  • 2017 iMac (Omarchy/Arch Linux) — always-on homelab server, runs the agent harness

Software stack

  • LM Studio — model serving with an OpenAI-compatible API
  • Ollama — lightweight model runner, part of the regular rotation
  • Open WebUI — chat interface for local models
  • Stable Diffusion — local image generation
  • Local agent harness — lives on the iMac, talks to the Mac Studio's models over the LAN

Why self-hosted

The honest reason: it's a hedge. Money's tight — I'm on the free tier and can't justify $20/month for Power. If pricing ever forces me off the paid tiers entirely, the work doesn't stop — the models are already here, on my machines, under my control. Independence isn't a philosophy project; it's what keeps the lights on.

The part that made the economics real for me: the API is metered per token, not flat. Architect-tier consults run cents a pop if you only call the architect when you need one. That's the whole design of the harness — a builder model for the routine work, the reasoning model only when the question earns it.

What broke and how it was fixed

The current lineup, as actually served: the builder and swarm run Qwen3-32B, the architect runs DeepSeek-R1-Distill-Qwen-32B, and a Qwen 35B A3B build sits as backup. Getting there was a whole saga of downloads, LM Studio's exact served identifiers (config model IDs have to match what LM Studio actually serves — no guessing), and one memorable exchange where LM Studio said port 1235 and I'd assumed 1234. "It says 1235 not 1234" — my words, in my terminal, fixing my own config.

The harness lives on the iMac and reaches the Studio at http://192.168.1.187:1235/v1. For a while the iMac couldn't reach it at all — the Studio's server was bound to localhost. That fix is mine to finish: the LAN serving has to be enabled on LM Studio's Server tab. One checkbox between the harness and a working two-machine setup.

Verdict

If your AI bill is a line item you're worried about, a Mac Studio and an old iMac get you a long way. Run the heavy models where the memory is, run the agents where the uptime is, and only pay per token when the question is worth it.
