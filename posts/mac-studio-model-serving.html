Serving local AI models over my home network

by D'Vaughn House

The goal

One machine in the house runs the models; every other machine — laptop, iMac, phone — just talks to it. No per-seat cloud subscription, no API meter running while I work. The Mac Studio is the engine room.

Hardware and cost

  • Mac Studio with M2 Ultra and 64GB of unified memory

Software stack

  • LM Studio — serves models over the local network through an OpenAI-compatible API, so anything that speaks the OpenAI API format can point at it
  • Ollama — lightweight model runner, part of the regular rotation

What broke and how it was fixed

The first problem was embarrassingly basic: "how do i find the studio lan ip" — my actual question. The answer: Option-click the Wi-Fi icon on the Studio, or System Settings → Wi-Fi → Details. It reported 192.168.1.187, and that went into the harness config.

Then the port. I had 1234 in the config because that's LM Studio's default. The Studio said otherwise — "it says 1235 not 1234." So the endpoint became http://192.168.1.187:1235/v1, verified in my own terminal.

Then the reachability failure: the iMac still couldn't see the server. The diagnosis was that LM Studio was bound to localhost only — serving to itself, not the network. And here's the part where I got corrected: the old advice was "enable Serve on local network" on the Server tab. That toggle doesn't exist anymore in current LM Studio. The current path is LM Link — the mesh-networking route, end-to-end encrypted, nothing public. I took that correction from my own research and it stands: don't hand out LAN-binding steps for a UI that no longer has them. I haven't set up LM Link yet — still exploring it — so the Studio-to-iMac link remains on the to-do list.

Verdict

Serving models on your LAN is three things: the right IP, the right port, and the server actually bound to the network instead of localhost. Check all three before you blame the model. And when the software's UI changes out from under the guides, believe the software, not the guides.
