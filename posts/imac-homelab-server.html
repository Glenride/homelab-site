Turning a 2017 iMac into a 24/7 homelab server

by D'Vaughn House

The goal

Give the operation an always-on box: scheduled jobs, self-hosted apps behind a reverse proxy, and a home for everything that shouldn't depend on a laptop lid staying open. The 2017 iMac — the same one that fought me through the Omarchy install — is that box now.

Hardware and cost

  • 2017 27" iMac (iMac18,3), repurposed — not retired
  • Omarchy / Arch Linux
  • Mac Studio on the same LAN as the model server and the file source

Software stack

  • Omarchy / Arch Linux — the operating system
  • Docker Compose — apps run as containers (hello-world verified clean post-install)
  • Nginx Proxy Manager — reverse proxy for self-hosted apps
  • Cloudflare Tunnel — exposes the iMac-hosted sites (dvaughnhouse.org, store) without port forwarding

What broke and how it was fixed

The machine that became a server didn't know it was one yet. One morning the sites went down with 502s. The Cloudflare tunnel was perfectly healthy — 8 active connections, routing both hostnames correctly. The problem was the iMac itself: I'd closed Docker, or the machine had slept. The tunnel was fine; there was just nobody home behind it. The fix was docker compose up -d on the ThinkTank OS stack, and the rule going forward: the iMac stays awake 24/7 with Docker running. Letting the display sleep is fine. Letting the system sleep takes everything offline.

The mystery of the crashing "muse". Notifications kept popping up saying things were crashing on the homelab — and clicking one opened something called "muse" that told me I lacked an API key. My actual question at the time: "Is my computer broken or is muse?" The answer: neither, exactly. The crashes were normal homelab service hiccups, and clicking an alert invokes an AI crash-explainer literally named "muse" that needs an API key nobody ever gave it. It was never the local-agent harness (that was never installed on the iMac). The machine wasn't broken. It was just confused about who "muse" was.

The migration. The site files lived on the Mac Studio (~/Sites, ~/sites2) and moved to the iMac's ~/projects over scp — slow going over the Studio's WiFi, but it got there. Core post-install came together the same week: WiFi on the right driver (192.168.1.191), Ethernet back (192.168.1.148), SSH installed and enabled, Docker verified.

Verdict

A homelab server is a mindset change more than a hardware one: the machine has to stay awake, Docker has to stay up, and when the sites 502, check the box before the tunnel. The tunnel is never the problem. The box is.
