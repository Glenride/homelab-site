No sound on a 2017 iMac running Linux is a known quirk, not a dead machine

by D'Vaughn House

The goal

Sound. Out of the speakers. On a machine whose speakers demonstrably work — they worked five minutes ago under macOS. My first question, honestly, was whether this was just a limitation of running Linux on a Mac. It's not. This should not be hard.

Hardware and cost

  • 2017 27" iMac (iMac18,3) with Cirrus Logic CS8409 audio codec

Software stack

  • Arch Linux (Omarchy)
  • cheapjourney/cs8409-apple-audio on GitHub — the community driver fix for this codec; I haven't tried it yet, it's next on my list

What broke and how it was fixed

This one's a known quirk, not a mystery: the 2017 iMac's internal speakers use a Cirrus Logic CS8409 codec that stock Linux drivers simply don't drive. The headphone jack usually works fine — which is the tell. If headphones work and speakers don't, your hardware is fine; it's a driver gap.

Diagnosis before surgery: check wpctl status — if you see Dummy Output, the system has no working audio device at all. Then plug in headphones and test. That thirty-second check tells you whether you're fighting hardware or software.

The fix path is the community driver at cheapjourney/cs8409-apple-audio on GitHub, which has been physically tested on the iMac18,3 running Omarchy.

Still open — and this is the honest part: I still haven't run the wpctl check or the headphone test, and there's a GitHub patch repo I still need to try. So the diagnosis on my machine is unconfirmed and no driver has been installed. This post documents the playbook, not a completed fix — the fix itself is still on the to-do list.

Verdict

Never recommend a driver fix before seeing the hardware readout. Check wpctl status, test the headphone jack, and only then reach for the community driver. On Apple hardware under Linux, "no sound" is almost always a known quirk with a known fix — not a dead machine.
